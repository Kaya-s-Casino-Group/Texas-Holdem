# 单 Scene 单章旅程

打开 `Assets/Scenes/SingleChapterAdventure.unity`，进入 Play。也可以使用 Unity 菜单 **工具 → 局外冒险 → 打开单章七站场景**。

场景由现有 `BattleDemo` 的保存版本复制，保留其牌桌、战斗时间线、角色展示、手牌交互和管理面板。整个 Run 不加载其他 Scene；局外 Canvas 与战斗根节点按规则阶段切换。`EventSystem` 独立于战斗根节点，局外页面始终能接收输入。

单局战斗已同步当前 BattleDemo 表现：按规则计分牌发射抛物线弹道、水平翻牌与窄拖尾，非计分牌同时向下飞出且无拖尾；顺子逐张发射并按规则击杀转火，群攻向实际目标分支，皇家同花顺有独立命中反馈。弃牌目标位于手牌区正下方，发牌锚点对齐牌堆，弃牌接近结束再补牌。怪物沿轮廓红色描边选中，血条、意图、状态使用跟随怪物屏幕投影的固定尺寸 UI，不受远近影响；死亡使用灰烬 Shader 消散，动态召唤和跨战斗复用恢复独立材质与进度。

选牌预览默认展示伤害、击杀和目标生命变化，筹码/倍率置于悬浮详情。遗物栏接入 12 张美术，悬浮显示效果及主动使用按钮，有限次数的主动道具在图标右下角显示剩余次数；六面骰在悬浮面板内选择替换对象。HUD 上的 `BattleDemoRelicArt` 可在 Inspector 调整图片映射、尺寸和间距。场景仍使用 SingleChapter 的遭遇、敌人数量与遗物持有状态，不使用 BattleDemo 的 600/4/6 验证编成。

后续可执行 **工具 → 局外冒险 → 同步单局战斗表现**，同步 BattleDemo 的弹道参数、灰烬时长、效果预览和遗物美术；工具仅更新这两个场景支持的专用表现，不替换冒险宿主、XML、布局或局外流程，不修改通用表现协议。

## 流程

主菜单 → 角色 → 开局塔罗 → 七站地图 → 节点内容 → 战斗奖励/本局结算。

```text
普通战斗 → 宝箱 → 普通战斗 → 商店/休息 → 精英 → 商店/休息 → 首领
```

主菜单支持继续、查看上局结算、只读塔罗图鉴、确认放弃本局。当前角色为愚者，角色选择、愚者塔罗与战斗共用现有主角立绘；更多角色和塔罗需要补充正式内容。

- 地图只展示节点类型与可达性，不提前泄露未来怪物详情。
- 商店显示本次固定的四格货架，道具详情和买卖、永久牌组删牌/复制/改花色都由规则层校验。
- 休息入场回血 **20**（XML 的 `restHeal` 可配置），抽奖可选且最多一次；关闭页面、菜单往返与读档均不重复回血或抽奖。
- 宝箱自动给金币与道具；满栏奖励逐件替换或放弃，处理完才能离开节点。
- 详情弹窗的关闭不会推进节点；只有离开/继续按钮提交 `Continue`。
- 推币机不在本版范围。

## 美术与布局

**工具 → 局外冒险 → 应用完整冥界UI** 可将当前皮肤同步到 BattleDemo 与 SingleChapterAdventure。主角恢复常规世界空间面片，保留原先的视口高度，按源图宽高比布局，完整 UV 采样，不使用最上层覆盖组件。卡牌、牌库弹窗与商店改牌缩略图统一使用 FourBeasts。

全流程采用黑曜石纹理、暗红主操作与金色边线。地图由下向上排列七站，直接点击节点图标，旁边保留地点名称与已完成提示。休息页背景为提供的篝火图。新生成的面板、地图、节点图集位于 `Assets/Art/UI/Underworld/Resources/RitualUI`，生成提示记录在同目录上两级的 `Generation.json`；所有图片以等比适配或等比裁切展示，不使用非等比拉伸。

牌区距相机 2，怪物面片距相机 6.4，保留原来的屏幕占位与等比尺寸，将前后距离从 1.2 拉开至 4.4。单张飞行时长为 0.64 秒，保留抛物线、翻牌、拖尾以及命中后结算的时序。

## 状态与存档

`AdventureSceneHost` 是整局唯一命令入口，实现 `IBattleSessionCommands`。玩家出牌、弃牌、回合推进、道具与管理操作都经由 `BattleAdventureSession` 提交；`SingleBattleSceneAdapter` 只消费已提交的结果并播放，不再自行开局或另建单场会话。

每次操作先 fork 规则状态、执行并校验，再原子写入存档，最后发布新状态。保存失败时保留旧状态与当前战斗显示。开战的 Start 只执行一次，恢复存档仅同步界面；战斗结算先保存，动画完成后才出现局外奖励页。下一战动态绑定敌方数量，召唤物和已结束的敌方展示不会带入下一战。

对局结束 UI 在战斗时间线、角色动作和手牌表现全部执行完后，再等待 1.5 秒显示（使用不受战斗速度影响的真实时间）。等待期间保留战斗画面，不能继续节点或返回菜单；单场战斗的胜败面板遵循相同规则。

存档位置为 `Application.persistentDataPath/single-chapter-run.json`，上一版写入备份为同路径 `.bak`。Run 与长期进度在同一快照内提交。快照 schema 4 校验内容指纹；旧 schema 或不匹配内容会显示无法载入，原文件保留，不静默重开。当前没有跨内容版本迁移与云存档。

## 内容与验证边界

内容文件位于本地 BattleToolkit 包：

- `Engine/Content/SingleChapterAdventure.xml`：路线、经济版本、回血、货架、改牌价格。
- `Engine/Content/SingleChapterBattle.xml`：战斗遭遇与十二件道具品质。
- `Engine/Content/SingleChapter.md`：数值、设计快照和战斗技能边界。

地图与经济沿用单章七站实现。精英接入已确认的 500 血流血与攻击增长规则；首领接入 1500 血暴怒、四饮血手和一束缚手，包含龟缩、独立大招、断手 R+8 再生及 20 轮判负。沿用七站原有遭遇与单位 ID、远端精英/Boss 美术和灰烬消散。2026-10-22 按用户后续决定将七站所有牌型的初始基础分及每级基础分增长清零，伤害按计分牌点数乘现有倍率结算；其余倍率及成长、牌型技能、道具与经济配置保持原规则。随后按主案 revision 4357 将玩家基础生命调整为 120（愚者开局 144）、两场小怪调整为 250 血／攻击 6 和 250 血／攻击 8，取消第二站旧 1.25 生命倍率；四只饮血手各治疗本体 10。顺子仍逐段攻击，同花改为额外乘 2、独立治疗 50%（用户确认），心连心仍加 30 个百分点，葫芦仍按三条／对子分别乘 1.5，皇家同花顺仍直接消灭。旧三章 `StandardAdventure.xml` 继续使用暴食节点。战斗内容指纹变化后旧七站存档仍按既有校验拒绝载入，并保留原文件；退出 Play、重新进入并新开七站旅程后读取新版配置。
