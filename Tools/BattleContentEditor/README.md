# 战斗内容工坊（本地 HTML 配置工具）

第一版外部配置工具：十类中文表单、类型化引用选择、XML 导入/导出、浏览器草稿及统一 C# 校验。不运行对局，不读写 Unity SO、场景或战斗存档；规则语义仍由现有 `BattleContentCompiler` 决定。

## 启动

需要 Python 3.9+、Mono（`mcs` 和 `mono`）。现有离线规则测试使用同一套 Mono 工具链，运行编辑器不需要 Unity、Node、npm 或第三方 Python 包。

macOS 可双击 `start.command`，或在项目根目录运行：

```bash
python3 Tools/BattleContentEditor/server.py
```

等终端出现地址后，用浏览器打开 **http://127.0.0.1:18765**。第一次启动先在临时目录编译当前规则程序集；关闭终端或 Ctrl+C 停止服务。启动器不会自动更新任何资产。

- 修改规则 C# 后需要重启服务，以重新编译；XML 编辑立即使用当前服务校验。
- 端口被占用时可加 `--port 18766`。浏览器草稿按地址/端口隔离，换端口前请下载草稿备份。
- 可通过 `POKER_CSC`、`POKER_MONO` 指定编译器和运行时路径。
- 本机服务只监听 `127.0.0.1`，按启动器打印的地址访问，不使用 `localhost` 别名。

## 策划使用流程

1. 点击“载入功能示例”熟悉配置，或导入现有 XML。
2. 左侧按战斗配置、角色与构筑、战斗能力、基础规则分组；搜索名称或 ID，打开具体条目。
3. 修改中文表单；空白可选字段表示继承默认值，显式填入 `0` 与留空不同。高级参数默认折叠。
4. 引用可输入 ID、用候选列表选择、打开可搜索的选择窗口，或点击 `+` 新建后自动引用；“查看”可跳转到定义。侧栏展示引用和被引用关系。
5. 编辑后自动延时调用 C# 校验，也可手动点击“校验内容”。点击错误或警告定位配置；字段级检查只提示输入，不能代替 C# 语义校验。
6. “保存草稿”或 Ctrl/⌘ S 保存本浏览器草稿；编辑会自动保存。第一次打开已有草稿时先提示恢复，不自动覆盖旧草稿。
7. “导出 XML”对当前修订重新执行 C# 校验，只有通过才下载。警告可导出；错误不能导出。源码区有未应用内容时，需要先应用或放弃修改。

十类内容：计分规则、公共战斗规则、牌型效果、状态、遗物、玩家模板、敌人模板、牌组、构筑、编成。嵌套行为、条件、效果与目标用相同表单编辑，可新增、移除和上下调整顺序。新建牌型规则会生成十种牌型；自定义计分由当前 C# 默认表展开；牌组可以一次添加标准 52 张牌，再编辑单张。

牌型步骤 ID 与效果顺序分开，重排不改 ID。遗物步骤选择器的“浏览步骤来源”只帮助列出指定规则/牌型的步骤，不写入遗物配置，也不假定所有玩家使用同一套牌型规则。修改/移除被匹配的步骤会展示可能受影响的遗物条目，实际编成组合仍由 C# 校验。

定义 ID 重命名时，会询问是否同步更新同类型引用；有引用的定义必须选择替代定义后才能删除。显示名称可自由修改。新增和复制自动生成不冲突的标识；复制构筑不会运行或消耗遗物。

## 导入与数据保护

- XML 文档是编辑数据源，表单编辑不会丢弃未知属性、子项和注释。未知/不适用字段在界面提示，可检查后显式移除。
- 修改能力类型或触发时机不会静默删除已有参数。需要清理的不适用字段会保留，正式导出由 C# 阻止。
- XML 语法/根格式无法读取时，当前内容包不被覆盖，原文保留在源码区供修复；规则错误但语法可读的内容作为草稿载入。
- “XML 预览”可查看或编辑完整文本；应用后重新生成对应当前文本的诊断位置。
- 草稿同时保存当前内容和未应用的源码。支持下载/恢复 `.draft.json`，也可在源码区下载明确标为 `.draft.xml` 的未校验文本。
- 草稿保存在当前浏览器、当前地址的 localStorage，可能受隐私模式/配额/清理影响；保存失败会提示下载备份。跨电脑/浏览器请使用文件备份。
- 支持最近 40 次内容修改撤销/重做，刷新后不保留撤销历史。服务离线仍保留表单和草稿；不能把离线当成校验通过。
- 数值作为字符串往返，避免 JavaScript 大整数精度损失。XML 格式化可能改变缩进和属性表示，但不把未知数据自动转换成“已支持”。

## 技术边界

```text
浏览器：schema.js 表单描述 + model.js XML 编辑 + app.js 交互
    POST /api/validate（当前 XML）
Python 本机 HTTP 服务（长度/来源检查、进程超时）
    Mono CompilerBridge.exe
现有 BattleContentXmlReader → BattleContentCompiler
    统一诊断 / 内容指纹
```

- `CompilerBridge.cs` 仅投影诊断和现有枚举/默认计分/标准牌面元数据，不实现战斗或复制规则校验算法。
- HTML 的字段可见性、类型化引用和中文说明属于编辑体验；编译器仍检查完整内容包，包括未使用的定义和实际编成组合。
- 页面没有第三方 CDN、统计服务或外部请求。服务不接收文件路径，不提供执行对局、写项目文件或任意静态文件读取接口。
- 导入/校验结果绑定内容修订；过期响应不会覆盖新修订。校验服务失败、超时或不可用时不会导出为正式内容。
- 为保护本机接口，服务检查 Host、同源 Origin 和页面会话令牌；不开放 CORS。CSP 禁止内联脚本和外部连接，名称/诊断通过文本节点呈现。
- 当前只支持单个 schema v1 内容包；不提供协作、热更新、多人草稿合并、批量平衡模拟、对局测试台或自动迁移旧 SO。

## 验证

后端集成（临时编译真实 C# 程序集，随机本机端口）：

```bash
python3 -m unittest discover -s Tools/BattleContentEditor/tests -p 'test_*.py' -v
```

浏览器回归需要额外安装测试依赖 Playwright 与 Chrome。先启动本地服务，再在本目录执行：

```bash
npm install
npm run test:browser
```

默认使用隔离的无头 Chrome，不连接用户日常浏览器。可用 `EDITOR_URL` 指定测试地址、`PLAYWRIGHT_CHANNEL` 指定渠道、`EDITOR_SCREENSHOT` 指定截图路径。浏览器测试会在隔离上下文里生成草稿与下载；服务本身不会保存这些文件。

原规则层回归：

```bash
bash Tools/test-poker-engine.sh BattleContentXmlReaderTests BattleContentEffectCompilationTests BattleContentCombinationTests BattleContentIntegrationTests
```

本次验证：后端集成 10 项、浏览器流程 23 项、既有 XML 内容规则回归 154 项全部通过。浏览器检查覆盖十类表单、引用重命名/删除、未知字段与注释保留、导入修复、草稿恢复、长整数、过期响应、离线导出阻止和 1100px 布局。
